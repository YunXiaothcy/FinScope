# 阶段 5：CSV / XLSX 账单导入

## 使用流程

打开账本右上角“账单导入”，或访问 `/workspaces/:workspaceId/imports`。流程为上传文件、确认列映射、查看每行错误和重复、勾选有效行、再次确认、查看结果报告。上传和预览均不产生账务交易。

本阶段采用规则解析和表头建议，不调用 AI，不把文件或财务数据传给第三方。只支持已实际发生的收入、支出；商户支出可映射到已有成本或费用分类。转账、退款、余额调整、借还款、应收应付及其结算须使用现有对应功能，防止把资金流错误计入收入或利润。

## 文件和清洗规则

- 文件最大 2 MiB，最多 1000 行数据和 40 列。第一行须是非空、无重复的表头；源数据和长备注中单元格最多 1000 字。
- CSV 尝试 UTF-8（含 BOM），再尝试 GB18030；支持逗号、分号、制表符。复杂银行文件应先移除说明行，整理为单行表头。
- XLSX 只读第一张普通工作表。使用 openpyxl 与 defusedxml；不执行公式或使用缓存计算结果。含公式/错误值的行标为错误；宏、外链、嵌入对象、加密、异常压缩文件及不安全 XML 被拒绝。压缩包最多 1000 项、总解压大小 10 MiB，不解压到磁盘。
- XLSX 金额使用单元格 OOXML 的原始十进制文本，绕开 openpyxl 数值转换中的 float。Excel 日期单元格使用库的日期处理；文本日期可指定年-月-日、日-月-年、月-日-年。
- 无时区日期按香港时间处理；带时区的 ISO 日期时间转为 UTC。日期范围 1970—2100 年。
- 空白和全角字符会标准化；合法千分位逗号会移除。金额须大于零，最多 16 位整数、2 位有效小数，不能包含货币符号；不会自动取绝对值或把负金额认作退款。
- 每批选择一个入账账户。来源分类非空时必须明确映射；来源分类空白才使用默认收入或支出分类。不会自动建立分类。未识别类型需要用户手动指定，禁止自动猜测退款、转账等特殊业务。
- 币种列有值时必须与空间基础货币一致；未映射时使用空间基础货币。不做汇率转换，用户需确认文件币种。

金额原值如果已经被 Excel 截断，解析器无法恢复。超过 Excel 有效数字范围的金额和来源单号，应在来源文件中保存为文本。

## 去重与一致性

1. 同空间相同文件字节的 SHA-256 命中待处理或已完成批次时直接打开原批次。已取消/过期的草稿可以重新上传。
2. 有来源单号：以账户、稳定来源名称、来源单号生成指纹；相同单号但金额不同仍提示重复，须人工核对。不同渠道使用不同名称，同一渠道后续保持名称一致。
3. 无来源单号：以账户、UTC 时间、类型、标准金额、商户和备注生成内容指纹，分类不参与指纹。缺少单号的一方会与以往导入内容比对，防止通过漏映射单号重复导入。
4. 内容相同的有效手工收支或结算也会提示重复。不同明确来源单号允许代表内容相同的真实多笔交易。去重是规则匹配，无法理解所有银行订单语义；改动时间/备注/账户、来源命名不一致等仍需人工核对。
5. 批内重复、既有导入重复、既有手工记录重复都标明原因，不允许勾选入账。确认前重新检查；预览后新增的重复行会在确认时跳过，并列入报告。
6. 确认只接受服务端当前预览中可入账的行 ID 和版本，不接受客户端自报交易金额。重新预览使旧版本失效。
7. 确认请求必须有 `Idempotency-Key`。同一编号和内容重试返回原报告；不同内容复用编号返回 409。批次完成后不能再次确认，所有创建交易、资金变动、来源指纹、审计和确认响应处于一个事务。
8. 任何所选行验证失效或中途写入异常都会整批回滚。SQLite 通过提前取得写锁、PostgreSQL 通过空间及批次行锁协调确认，数据库另有指纹唯一约束。PostgreSQL 行锁尚未在实例上实测。
9. 已导入交易标记 `source=import`，继续支持账本编辑、退款和撤销。来源指纹保留，避免撤销后重新上传旧账单意外恢复入账；需要更正时在账本处理。
10. 批次完成后，未选择的有效行记为 skipped，不留待在原批次二次确认；请整理剩余行到新文件继续处理。

## 安全与数据保留

- 所有接口验证登录和空间成员资格；写操作要求非只读角色及 CSRF。账户、分类、批次和入账交易须属于同一空间，关联表另有复合外键约束。
- 原文件仅在内存解析，不写上传目录；文件名拒绝路径和控制字符。文件名通过请求头传递，避免出现在访问日志的 URL 参数中。
- 原始预览行仅保存在服务端数据库中；72 小时后访问导入列表、批次或上传时清理。该机制是访问时清理，尚无定时删除任务，不承诺精确到点清理。取消草稿立即清理原始行和标准化预览。
- 已入账交易、来源指纹、标准化入账记录与批次必要元数据继续保留用于去重和审计；清理原始行不删除账务。
- 浏览器仅会话暂存待确认请求编号、批次及行 ID，不暂存原文件和金额；退出时复用账号模块清理。POST/PUT 确认并通过历史批次恢复，读取响应禁止缓存。
- 错误响应不回显完整文件内容；前端使用文本插值展示原始行，不执行单元格内容。

## 主要文件及接口

| 文件 | 用途 |
| --- | --- |
| backend/app/services/import_parser.py | 文件大小/结构限制、CSV/XLSX 安全解析、保留数值原文 |
| backend/app/services/import_batch.py | 日期金额清洗、映射校验、去重、确认入账、过期清理 |
| backend/app/models/import_batch.py | ImportBatch 批次、ImportRow 来源行及去重/交易关联 |
| backend/app/schemas/import_batch.py | 映射、确认请求与结果模型 |
| backend/app/api/v1/imports.py | 上传、列表、读取、预览、确认、取消 REST 接口 |
| backend/alembic/versions/0004_import_batches_import_batches.py | 新表、外键、索引、状态检查和指纹唯一约束 |
| frontend/src/views/ImportView.vue | 导入工作台、勾选确认、报告和安全重试 |
| frontend/src/api/imports.ts / utils/imports.ts | API 调用、表头建议、来源值收集和虚构示例 |
| backend/tests/test_imports.py / test_import_concurrency.py | 文件安全、金额、权限、去重、事务回滚与并发测试 |
| frontend/tests/imports.test.mjs | 表头建议、来源值规范化和演示文件检查 |

接口前缀：`/api/v1/workspaces/{workspace_id}/imports`。

- `POST` 根路径：直接上传二进制内容，`Content-Type: application/octet-stream`，`X-File-Name` 为 URI 编码文件名；成功返回批次，不入账。
- `GET` 根路径：最近 50 个批次；`GET /{batch_id}`：批次、行和结果。
- `PUT /{batch_id}/preview`：提交 `version` 与 `mapping`，重算预览。
- `POST /{batch_id}/confirm`：提交 `version`、选中 `row_ids` 和请求编号，原子确认。
- `POST /{batch_id}/cancel`：提交 `version`，取消草稿。

本阶段不提供银行平台专用适配、行内编辑、导出报表、OCR 或 AI。手机操作及浏览器端到端仍需按 README 人工验收。

解析行为参考 [openpyxl 读取参数](https://openpyxl.readthedocs.io/en/3.1/api/openpyxl.reader.excel.html) 和 [Excel 日期系统](https://support.microsoft.com/en-gb/excel/date-systems-in-excel)。
