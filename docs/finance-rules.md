# 阶段 2 账务规则

## 金额与货币

金额输入使用十进制字符串，最多 16 位整数、2 位小数；拒绝浮点输入和超出精度的金额，避免悄悄截断。Python 计算使用 Decimal，PostgreSQL 字段是 NUMERIC(18,2)。SQLite 不具备原生定点小数，因此本地开发模式使用整数分保存；读取时恢复 Decimal，不经过 float。

阶段 2 支持 CNY、HKD、USD、EUR，统一两位小数；同空间内账户均使用基础货币，不混合币种汇总。期初余额允许负数，例如信用账户初始欠款。余额可为负数，本阶段不强制透支限制。

## 余额、收支与退款

账户余额 = 创建时的期初余额 + 全部资金变动之和。期初余额固定，不参与本期收入。收入增加账户余额，支出减少余额。内部转账一次性产生一负一正两条等额资金变动，两个账户和转账记录在同一数据库事务提交。

退款关联有效的原收入或原支出，沿用原账户和分类。退回支出会减少净支出；退回收入会减少净收入。累计有效退款不能超过原金额，时间不能早于原交易。有退款的原交易须先撤销退款，才能编辑或撤销原交易。退款本身不直接编辑，可撤销后重登。

余额调整只改变余额，不参与收入、支出或商户利润。该功能用于带原因的对账修正；借款、注资等非经营流入不能登记成经营收入，当前尚无它们的专门明细管理。

## 历史记录与并发

编辑或撤销不删除资金变动：系统追加对应反向记录，编辑时再登记新的资金变动。原始资金变动、冲销关系和审计前后值保留。资金变动的 created_at 是实际记入时间，交易 occurred_at 是业务发生时间；两者不可混同。

交易和转账创建采用按用户、工作空间限定的幂等键，相同键和相同内容重试返回第一次响应；相同键搭配不同内容返回 409。记录、资金变动、审计与幂等响应在同一数据库事务内提交。即使原记录之后被修改或撤销，重试旧创建请求也只返回旧响应，不会恢复或创建另一笔记录。

编辑与撤销需要客户端提交 version，版本已变化返回 409。PostgreSQL 使用行锁协调原交易与退款；本地 SQLite 使用写事务锁防止并发退款超额。只读成员可查看，不能修改；所有关联账户、分类、原交易须属于当前授权空间，数据库复合外键再次约束归属。

## 统计口径

本期收入和支出以香港时间选择的起止日期统计，结束日期包含整日。退款在退款发生期冲减原类型，所以跨期退款可能使当期净收入或净支出为负。分类汇总使用相同口径。

本期结余 = 净收入 − 净支出。本期净资金变动 = 本期结余 + 净调整；内部转账在空间内净额为零。页面总余额包含期初及全部已确认记录，与所选收支周期独立。该模型服务于个人管理分析，不是正式复式会计账簿。

流水每页 50 条，API 每页最多 200 条；转账与账户资金变动视图显示最近 200 条，操作记录显示最近 100 条，余额计算始终使用全部资金变动。
