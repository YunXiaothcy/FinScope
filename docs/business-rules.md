# 阶段 3 商户口径

## 利润和现金流

简化利润 = 营业收入 − 经营成本 − 经营费用。金额由后端 Decimal 程序计算，前端只展示返回的十进制字符串。

即时收支按交易发生时间确认营业收入、成本或费用；已登记为应收应付的业务按业务确认时间计算利润，其后收付款仅影响现金流。此口径用于小微商户管理分析，不包含库存结转、税费拆分、折旧、预提摊销或正式会计关账。

例如确认客户欠款 800 元，利润中的收入增加 800 元，银行余额不变。之后收款 500 元，银行余额增加 500 元，应收余额剩 300 元，利润不再增加。采购应付使用同样规则：确认时增加成本或费用，支付时仅减少账户余额和未付款。

分类有固定的经营口径：收入分类属于 revenue；支出分类属于 cost 或 expense。旧收入默认归营业收入、旧支出默认归经营费用。经营口径创建后不能直接改写，以免历史数据随意改变；如需更正，新增正确分类并通过审计保留的交易编辑纠正。应收应付录错时撤销后重新登记。

## 应收应付和结算

应收只能选择收入分类，应付只能选择成本或费用分类，所有分类和结算账户必须属于当前商户空间。到期日不能早于业务确认日期；本阶段结算时间不能早于业务确认时间。

一笔应收应付可多次部分结算，累计有效结算不得超过总额。每次结算会生成一笔 source=settlement 的收入或支出交易，复用账户资金变动、幂等、审计和权限机制。结算不进入第二次利润计算。结算条目不能直接编辑或退款，录错时撤销并重新结算；撤销追加反向资金变动、恢复未结余额并推进版本号。

应收应付数据库保存 posted/voided 记录状态，unsettled/partial/settled/voided 结算状态由有效结算计算，避免同时保存多个容易不一致的余额。所有有效结算撤销后才能撤销原应收应付。撤销用于更正错误记录，当前没有应收减免、信用票据或真实跨期退货功能；不要用撤销冒充这些业务。

创建业务和结算均要求 Idempotency-Key，结算指纹包含原记录 ID。重复重试返回第一次响应；同一编号用于不同业务或内容会返回 409。结算还需提交读到的 version；另一次结算或撤销改变版本时必须刷新。SQLite 使用写锁，PostgreSQL 使用行锁协调金额检查。

## 现金流与报表周期

实际流入包含收到的款项和支出退款，实际流出包含支付的款项和收入退款。收付净现金流 = 实际流入 − 实际流出。余额调整单列，本期净资金变动 = 收付净现金流 + 净调整。空间内账户转账净额为零，不增加收入或利润。

期初余额 + 本期净资金变动 = 期末余额。这里的期初、期末使用当前有效交易按业务发生时间重新计算；编辑或撤销会重算历史报表，不提供关账后的历史快照。当前账面总余额仍由期初账户金额加全部资金变动计算。

利润和现金流按香港时间所选起止日期统计，结束日包含整日。应收应付报表余额只计算结束日前已确认业务、扣除结束日前有效结算；逾期指标指到期日早于所选结束日的未结余额。台账列表则显示全部已登记结算的状态，因此历史报表与当前列表状态可以不同。

账户流水页面的收入/支出是收付款口径，包含应收应付结算；经营利润应查看商户经营页面。直接记账的退款按退款日期冲减原经营分类；借款、注资和余额调整不计入本阶段利润。当前不提供贷款或股东权益专门明细。

## 接口和查看权限

接口位于 /api/v1/workspaces/{workspace_id}/business 下：report 返回指标、类别汇总与每日明细；obligations 创建或列出应收应付；obligations/{id}/settlements 登记和查看结算；obligations/{id}/void 撤销原业务。结算撤销复用 finance/transactions/{id}/void。

仅商户空间提供这些接口；个人空间返回 403，非成员空间返回 404。viewer 可读报表但不能修改。台账每页最多 200 条，前端每页 50 条；统计使用全部有效数据。
